# 场景一：个人知识库

## 场景定义

知识库存在的目的是为了个人将日常看到的外部信息源和自己的思考规整下来，通过对信息源的处理和补充个人思考，最终产出某种综合分析或产品分析，并输出文档。

典型用户：研究者、创业者、投资人、内容创作者、KOL。

## 访谈流程

场景一的核心是搞清楚三件事：**你消费什么、你怎么思考、你想产出什么。**

访谈按以下顺序展开，每组问题问完后简要复述用户回答，确认理解再继续下一组。

### 第一步：信息消费

提问：
1. 你日常会看哪些类型的外部内容？（文章、播客、视频、论文、书籍……）
2. 你一般从哪些渠道获取？（微信公众号、Twitter、播客 App、行业报告……）
3. 你看完之后通常会做什么？（做笔记、跟朋友讨论、写总结、直接忘掉……）
4. 能不能给我一个你最近看过、觉得特别有价值的内容的链接或文件？

访谈目的：确定 `raw/` 目录的子目录结构，以及信源质量层级。

第四个问题特别重要——拿到一个真实内容种子，就可以当场演示完整流程，让用户理解知识库的价值不只是"存东西"，而是"处理+关联+产出"。如果用户当下手边没有，问"你最近印象最深的一篇是什么"，让用户口述也行。

### 第二步：个人思考

提问：
1. 你看完外部内容后，会有自己的判断和思考吗？
2. 这些思考你平时记录在哪里？（手机备忘录、微信收藏、聊天记录、脑子……）
3. 你的思考通常是关于什么的？（行业趋势、产品想法、技术判断、组织管理……）
4. 有没有一个你最近想到的、想记录下来的想法？

访谈目的：确定 `wiki/thoughts/` 的定位和内容方向，以及 `raw/thoughts/` 的摄入方式。

很多用户会说"我思考了但没记下来"——这恰恰说明知识库的价值。引导用户口述一个最近的思考，当场演示从口述到结构化 thoughts 页面的过程。

### 第三步：产出目标

提问：
1. 你希望这些积累最终能帮你产出什么？（深度分析文章、产品方案、投资决策、培训材料……）
2. 你之前产出过类似的东西吗？如果有，当时的流程是怎样的？
3. 你觉得之前产出过程中最耗时的环节是什么？

访谈目的：确定 `wiki/synthesis/` 和 `wiki/outputs/` 的产出类型。

产出目标决定了知识库的组织重心。如果用户想产出投资决策，concepts/ 应该侧重投资框架和判断标准；如果想产出内容文章，concepts/ 应该侧重观点和叙事角度。

### 第四步（可选）：共享模式

仅当用户表现出明确的共享意愿时才进入。

提问：
1. 你是否希望把你筛选的优质信息源整理后开放给其他人？
2. 你是否希望把你的个人思考作为知识型内容发布？
3. 如果要共享，你的受众是谁？他们需要什么形式的内容？

## 边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 用户说"我什么都看" | 追问"最近一周实际看了什么"，用具体行为确定真实信源类型 |
| 用户说"我没什么思考" | 换个问法："看完一篇好文章后，你有没有觉得'这个观点我不同意'或'这个可以用在我的项目上'？" |
| 用户说"我还没想好产出什么" | 先不建 synthesis/ 和 outputs/，后续有了再加 |
| 用户拿不出内容种子 | 先完成框架搭建，告知用户"下次你看到好内容直接发给我" |

## 访谈结果记录

```yaml
场景: 个人知识库
信源类型: [文章, 播客, 视频, ...]
信源渠道: [微信公众号, 播客App, ...]
信源处理习惯: [做笔记, 讨论, 写总结, ...]
思考记录方式: [备忘录, 聊天记录, ...]
思考方向: [行业趋势, 产品想法, ...]
产出目标: [深度分析, 产品方案, ...]
产出痛点: [最耗时的环节]
共享意愿: [无 / 信息源共享 / 思考共享 / 两者都有]
内容种子: [提供的真实内容链接或文件]
```

## 翻译规则

### 访谈结果 → 目录结构

| 访谈维度 | 映射到目录 | 说明 |
|---------|-----------|------|
| 信源类型 | `raw/articles/`、`raw/podcasts/`、`raw/videos/` 等 | 按实际消费类型建子目录 |
| 个人思考 | `raw/thoughts/` + `wiki/thoughts/` | raw 存原始，wiki 存结构化 |
| 产出目标 | `wiki/synthesis/` + `wiki/outputs/` | synthesis 存分析，outputs 存成品 |
| 信源处理后 | `wiki/sources/` | 每篇外部资料的摘要页 |
| 人/组织/产品 | `wiki/entities/` + `wiki/products/` | 从信源提取的实体 |
| 概念/方法 | `wiki/concepts/` | 从信源提炼的概念 |
| 案例 | `wiki/cases/` | 信源中的具体场景 |
| 共享意愿 | `wiki/published/`（如有） | 精选信源和思考的发布版 |

只创建用户会用到的目录。如果用户没有视频信源，就不要建 `raw/videos/`。空目录不仅没有意义，还会让用户困惑"这个目录是干什么的"。

### 访谈结果 → AGENTS.md 工作流

| 访谈维度 | 映射到工作流 |
|---------|------------|
| 信源处理习惯 | "摄入外部资料"工作流 |
| 思考记录方式 | "摄入个人思考"工作流 |
| 产出目标 | "产出综合分析"工作流 |
| 产出痛点 | 工作流中的优化点 |
| 共享意愿 | "整理发布"工作流（如有） |
